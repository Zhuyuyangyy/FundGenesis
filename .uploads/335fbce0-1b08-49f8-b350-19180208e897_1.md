# 0. 最终定位：FundGenesis 到底要成为什么

FundGenesis / ReflexMarket-AI 的最完美形态不是：

```text

可复现、可审计、论文级、交互式金融反身性世界模型实验室。
```

# ReflexMarket Lab

## 3.2 P0 必须解决的 7 个问题

### 问题 1：`net_demand` 跨步累积

当前市场环境中如果 `net_demand` 没有严格按 step 重置，会导致上一轮订单流残留影响下一轮价格。

正确设计：

```text
begin_step()
  清空 step_orders
  清空 step_buy_volume
  清空 step_sell_volume
  清空 step_net_demand

agents_decide()
  每个 Agent 产生订单

submit_orders()

compute_order_imbalance()

update_price()

record_history()

end_step()
```

必须区分：

```text
step_net_demand：当前 step 的净需求，只影响当前价格冲击
cumulative_net_demand：历史累计净需求，只用于图表和统计
```

验收测试：

```python
def test_net_demand_resets_each_step():
    market = MarketEnvironment(initial_price=100)

    market.begin_step()
    market.submit_order(buy_order(volume=10))
    market.update_price()
    assert market.step_net_demand > 0

    market.begin_step()
    market.update_price()
    assert market.step_net_demand == 0
```

### 问题 2：FOMO 没有真正接入 EmotionField

FOMO 不能只是风险模块内部的记录。

它必须进入情绪场：

```text
FOMO detected
→ greed 上升
→ retail buy pressure 上升
→ order imbalance 上升
→ price momentum 上升
→ bubble risk 上升
```

新增接口：

```python
def apply_fomo_signal(
    self,
    intensity: float,
    source: str = "manipulation_risk_agent",
    decay: float = 0.85,
):
    intensity = np.clip(intensity, 0.0, 1.0)

    self.greed = np.clip(
        self.greed * decay + intensity * (1.0 - decay),
        0.0,
        1.0,
    )

    self.fomo_pressure = np.clip(
        getattr(self, "fomo_pressure", 0.0) * decay + intensity,
        0.0,
        1.0,
    )
```

验收标准：

```text
开启 FOMO→Emotion：
greed 峰值上升；
retail buy ratio 上升；
order imbalance 上升；
bubble_risk_score 上升。

关闭 FOMO→Emotion：
上述指标明显降低。
```

### 问题 3：KOL `belief_state` 基数过低

不能让 KOL belief 长期停在 `0.003-0.005` 这种不可观测区间。
但也不能粗暴乘大常数。

正确方案：

```text
exposure accumulation
trust-weighted propagation
layer-specific susceptibility
bounded nonlinear activation
belief decay
max_delta_per_step
```

推荐公式：

```python
raw_exposure = (
    narrative.strength
    * source.influence_score
    * trust_score
    * propagation_probability
)

target.cumulative_exposure += raw_exposure

belief_delta = np.tanh(
    exposure_gain * target.cumulative_exposure
)

belief_delta = np.clip(
    belief_delta,
    -max_belief_delta_per_step,
    max_belief_delta_per_step
)

target.belief_state = np.clip(
    target.belief_state * belief_decay + belief_delta,
    -1.0,
    1.0,
)
```

目标阈值：

| 层级         |                    目标 |
| ---------- | --------------------: |
| Macro KOL  | `belief_state > 0.25` |
| Influencer |  `mean_belief > 0.15` |
| Micro      |  `mean_belief > 0.08` |
| Retail     |  `mean_belief > 0.03` |

你上传的 P0 记录中已经显示，经过调整后 KOL belief 的多层级阈值可以全部通过，例如 Macro、Influencer、Micro、Retail 均进入可观测范围。

### 问题 4：`id(narrative)` vs `narrative._id` 键不匹配

这是非常关键的 bug。

错误模式：

```python
nid = id(narrative)
```

但记录传播时用的是：

```python
risk_agent.record_kol_spread(shared_narrative._id, kol_id)
```

如果检测器用 `id(narrative)`，记录器用 `narrative._id`，那么永远匹配不上。

修复：

```python
nid = narrative._id
```

否则权重最高的 coordinated KOL amplification 模式会长期失效。

---

### 问题 5：风险评分公式不读取干预修改字段

这是监管实验不分化的核心原因。

当前干预修改的是：

```text
narrative_throttle → narrative_strength_multiplier
kol_downweight → kol.influence_score / kol.trust_level
risk_warning → agent.fomo_sensitivity
trading_cooldown → agent.trade_frequency
```

但风险评分必须实际读取这些字段，否则干预只是“改了变量”，没有进入指标系统。

修复方向：

```text
coordinated_kol_amplification 应读取 influence_score / effective_influence
retail_fomo_surge 应读取 agent.fomo_sensitivity / trade_frequency / retail_buy_pressure
price_narrative_self_validation 应读取 effective_narrative_strength
abnormal_trust_building 应读取 TrustEngine 中真实 effective_trust，而不是孤立的 KOL 字段
```

最终评分需要显式引入：

```python
intervention_adjusted_score = raw_score * narrative_multiplier * influence_multiplier * trading_activity_multiplier
```

但注意：不要简单“监管一开，风险分打折”。更好的方式是让干预先改变状态，再让状态自然影响风险分。

---

### 问题 6：执行顺序错误

错误顺序：

```text
risk_agent.evaluate()
regulator.step()
```

这样当前 step 的干预永远影响不到当前 step 的风险分。

正确顺序有两种。

推荐方案 A：用上一轮风险驱动本轮监管

```text
1. begin_step
2. 根据 prev_risk_score 执行 regulator.step()
3. narrative propagation
4. belief update
5. emotion update
6. agents decide
7. market update
8. reflexivity_monitor.observe()
9. risk_agent.evaluate()
10. 保存 current_risk_score → 下一步使用
```

也就是：

```python
prev_risk_score = 0.0

for step in range(steps):
    regulator.step(prev_risk_score, world_state)

    step_engine.run_market_cycle()

    current_risk_report = risk_agent.evaluate(world_state)
    prev_risk_score = current_risk_report.manipulation_risk_score
```

推荐方案 B：双评估

```text
pre_risk = risk_agent.evaluate()
regulator.step(pre_risk)
post_risk = risk_agent.evaluate()
```

论文实验中可以同时记录：

```text
pre_intervention_risk
post_intervention_risk
risk_reduction_delta
```

### 问题 7：`bubble_risk_score` 饱和

如果 `bubble_risk_score` 动不动就 clip 到 `1.0`，干预再有效也看不出来差异。

要修复：

```text
降低 belief_boost 系数；
降低 emotion_boost 系数；
降低 volatility_momentum 系数；
保留 raw_bubble_risk 和 clipped_bubble_risk；
论文和 benchmark 用 raw + clipped 双指标。
```

建议：

```python
bubble_risk_raw = (
    belief_boost
    * emotion_boost
    * volatility_momentum
    * capital_factor
    * narrative_factor
)

bubble_risk_score = np.clip(bubble_risk_raw, 0.0, 1.0)
```

输出必须包含：

```json
{
  "bubble_risk_raw": 1.37,
  "bubble_risk_score": 1.0,
  "saturated": true
}
```

## 4.1 新增 `WorldState`

所有模块状态必须统一收口。

```python
@dataclass
class WorldState:
    step: int
    timestamp: float

    market: MarketState
    emotion: EmotionState
    narratives: list[NarrativeState]
    agents: list[AgentState]
    kol_network: KOLNetworkState
    trust: TrustState
    risk: RiskState
    regulation: RegulationState

    events: list[SimulationEvent]
    metrics: dict[str, float]
    metadata: dict[str, Any]
```

好处：

```text
可以保存快照；
可以断点续跑；
可以回放；
可以生成论文图；
可以做 dashboard；
可以做 provenance audit。
```

## 4.2 新增 `EventBus`

所有关键变化都要事件化。

事件类型：

```text
NarrativeInjected

TrustUpdated

EmotionUpdated
OrderSubmitted
OrderImbalanceComputed
PriceUpdated
ReflexivityMeasured
RiskDetected

```

事件格式：

```python
@dataclass
class SimulationEvent:
    event_id: str
    step: int
    event_type: str
    source: str
    target: str | None
    payload: dict[str, Any]
    before: dict[str, Any] | None
    after: dict[str, Any] | None
```

每个事件都要回答：

```text
谁触发了？
影响谁？
改了什么？
改前是多少？
改后是多少？
发生在哪一步？
```

## 4.3 新增 `StepEngine`

所有 demo 都必须走统一 StepEngine。

```python
class StepEngine:
    def run_step(self, world: WorldState, scenario: ScenarioConfig):
        self.process_scheduled_events(world)
        self.apply_regulation_from_previous_risk(world)
        self.propagate_narratives(world)
        self.update_trust(world)
        self.update_beliefs(world)
        self.update_emotions(world)
        self.collect_agent_orders(world)
        self.update_market(world)
        self.compute_reflexivity_metrics(world)
        self.detect_risk(world)
        self.record_snapshot(world)
        return world
```

禁止模块绕过 StepEngine 直接改价格。

每个结果输出：

```text

effect size

```

## 6.2 消融实验

必须做 8 组：

| 模型                  | 移除模块      | 目的                     |
| ------------------- | --------- | ---------------------- |
| Full                | 无         | 完整闭环                   |
| NoNarrative         | 移除叙事      | 证明叙事不是装饰               |
| NoKOL               | 移除 KOL 网络 | 证明社会传播有贡献              |
| NoTrust             | 固定信任      | 证明 trust evolution 有贡献 |
| NoEmotion           | 移除情绪场     | 证明情绪放大有贡献              |
| NoPriceConfirmation | 移除价格确认    | 证明反身性反馈                |
| NoRiskAgent         | 移除风险检测    | 证明风险模块作用               |
| NoRegulator         | 移除监管      | 证明干预有效                 |

指标：

```text
price_peak
bubble_risk_peak
panic_risk_peak
reflexivity_index_peak
high_risk_steps
time_to_peak
max_drawdown
crash_probability
false_positive_rate
intervention_effect
```

---

## 6.3 统计检验

对每个关键指标做：

```text
bootstrap 95% CI
Mann-Whitney U test
Cliff's delta
paired seed comparison
```

例如：

```text
Full vs NoEmotion:
bubble_risk_peak ↑
retail_buy_ratio ↑
price_peak ↑
p < 0.05
effect_size > 0.5
```

---

## 6.4 假阳性控制

论文里一定要证明系统不会“一有波动就报风险”。

低风险场景：

```text
低强度叙事
低信任 KOL
随机中性新闻
高噪声但无 KOL 协同
低流动性自然波动
单个 KOL 发声
```

验收：

```text
manipulation_risk_score 不应长期超过阈值；
bubble_risk 不应误报；
FOMO 不应在低参与度场景中触发。
```

---

## 6.5 失败案例分析

论文必须主动写失败边界。

包括：

```text
KOL 网络过密导致信念同质化；
监管过强导致 panic_risk 上升；
低流动性市场中价格过度敏感；
高噪声场景下 narrative alignment 降低；
强叙事但低交易参与时泡沫无法形成；
多叙事冲突导致 regime detection 不稳定。
```

这会让论文更可信。

# 最终结论

FundGenesis 最终应该成为：

```text
ReflexMarket Lab：
一个研究金融市场中“叙事如何变成价格，价格又如何反过来强化或击碎叙事”的
多智能体、可复现、可审计、交互式世界模型实验室。
```

它的护城河不是“会写金融文本”，而是：

```text
可解释的机制；
可复现的实验；
可验证的指标；
可审计的结论；
可交互的世界模型；
可扩展的 Benchmark；
可论文发表的实验体系。
```

路线执行优先级永远是：

```text
机制可信 > 架构清洁 > Benchmark 标准 > 论文验证 > 可视化演示 > LLM 扩展 > 历史对齐 > 企业部署
```

现在最应该做的第一件事仍然是：

```text
完成 P0 的最终回归测试和 P0_FIX_REPORT.md，
然后立刻进入 P1：WorldState + EventBus + StepEngine。
```

只要 P0 和 P1 做扎实，后面的 Benchmark、论文、Dashboard、LLM、历史重放和企业级交付都会自然长出来。
